1. 整條 pipeline

clean datax₀ from GMM
forward noisemake_diffusion_batch → x_t
predict noiseNoisePredictorMLP(x_t,t) → ε̂
estimate cleanε̂ + x_t → x̂₀
reverse updateDDIM / DDPM / η → x_s
Training 和 sampling 學的不是同一件事。 Training 的 supervised target 是「剛才加進去的 noise ε」。Sampling 才拿 model 的 prediction ε̂ 去反推 clean sample，然後一步一步生成資料。

2. 四條核心公式

A. Schedule

αₜ = 1 − βₜ     ᾱₜ = ∏ᵢ₌₁ᵗ αᵢ
ᾱₜ 是最重要的 lookup value：到了 timestep t，原始 signal 還剩多少。

B. Forward marginal

xₜ = √ᾱₜ x₀ + √(1−ᾱₜ) ε
不用真的一步一步加 noise。給定任何 t，可以直接從 clean x₀ 做出那個 noise level 的 x_t。

C. Training objective

L(θ) = E || ε − ε̂θ(xₜ,t) ||²
因為 noise 是我們自己抽的，所以 ground truth ε 已知。model 就做 regression。

D. Clean estimate

x̂₀ = [xₜ − √(1−ᾱₜ) ε̂] / √ᾱₜ
Sampling 時每一步都會先做這件事：用 model 猜到的 noise 把 clean sample 倒推出來。

3. T 和 NFE 不要混在一起

T = diffusion schedule resolution

目前 code 是 T=300。Schedule 裡有 300 個 forward noise levels，training 會隨機抽其中一個 t。

make_diffusion_schedule 建的是這張 0…T 的 noise lookup table。

NFE = sampling model calls

目前比較 NFE = 1, 5, 20, 100。Sampling 不必走完 300 個 timestep；它用 make_sampling_timesteps 從 T 到 0 挑出 NFE 個 reverse jumps。

所以 T=300 不代表 sampling 一定跑 300 次 model。

為什麼現在 T=300 還乘 1000/300？ Textbook linear β range 1e-4 → .02 原本是 1000-step 設定。現在用 300 steps，所以 β range 乘 1000/300，目的是讓 terminal noise level 大致接近 textbook 1000-step process，而不是單純把 process 截短。 
# experiments/common.py
NUM_DIFFUSION_STEPS = 300
BETA_START = 1e-4 * 1000 / NUM_DIFFUSION_STEPS
BETA_END   = 0.02 * 1000 / NUM_DIFFUSION_STEPS
NFE_VALUES = [1, 5, 20, 100]

4. DDIM、DDPM、η 到底差在哪

三者每一步前半段其實一樣：拿現在的 x_t → model 預測 ε̂ → 算 x̂₀。真正不同的是「怎麼從 t 更新到下一個 s」。

SamplerFresh random noise?核心想法Project 裡的角色
sample_ddimNodeterministic path；重用 predicted noiseη = 0 endpoint
sample_etaControlled by ηη 從 0 到 1 調 stochasticityTask 006 mechanism sweep
sample_ddpmYes從 respaced jump posterior 抽樣η = 1 endpoint
sample_sigma_hatYes, larger variance用 DDIM paper Table 1 的較大 variance choicestochasticity control

Generalized η update

xₛ = √ᾱₛ x̂₀ + √(1−ᾱₛ−σ²) ε̂ + σz

σ = η √posterior_variance。η=0 時最後一項消失，就是 deterministic DDIM；η=1 時對應 DDPM jump posterior 的 stochasticity。

為什麼 Task 006 有意義？ Learned model 中 η 越大 SWD 越低；換成 exact oracle score 後，某些 NFE 的方向反轉。這讓我們可以問：stochasticity 是在補 learned-model error，還是在處理 finite-step sampler error？

5. Oracle score 是什麼

OracleNoiseModel 不需要 training。因為 GMM 加 Gaussian noise 後仍然是 GMM，所以在任意 t，我們知道每個 component 的新 center 和 variance，也能算 exact score。

Noised component

centerₖ(t) = √ᾱₜ μₖ
sₜ² = ᾱₜ σ₀² + (1−ᾱₜ)

Score → noise prediction

ε̂ = −√(1−ᾱₜ) · score(xₜ,t)
所以 oracle 可以直接塞進同一套 DDIM / DDPM / η sampler；唯一換掉的是 learned network。
這是很乾淨的 control：如果 learned model 和 oracle 的 η effect 不一樣，差異就不能全部怪 sampler formula；model approximation error 也是候選來源。

make_diffusion_schedule(num_steps, beta_start, beta_end)
Schedule

建立 betas、alphas、alpha_bars。真正後面一直 lookup 的是 alpha_bars[t]。

Remember β 是每一步新增多少 noise；ᾱ 是到目前為止累積還剩多少 signal。

make_sampling_timesteps(num_diffusion_steps, nfe)
Schedule

把完整的 0…T grid respacing 成 T=t₀ > t₁ > … > t_K=0，其中 K = NFE。

目前 implementation 是 linspace(T,0,nfe+1).round()。

NoisePredictorMLP
Model

Input 是 noisy sample x_t 加 normalized time t_model；output 維度跟 data 一樣，是 ε̂。

它不是直接輸出 x₀、density 或 score；目前 training objective 是 epsilon prediction。

OracleNoiseModel
Control

用 noised GMM 的 closed-form density responsibilities 算 exact score，再轉成 ε̂。API 刻意做得跟 learned model 一樣，所以 sampler 不需要改。

Used in Task 006 oracle η sweep。

make_diffusion_batch(batch_size, cfg, means, alpha_bars)
Training

一次做四件事：sample clean x₀ → random t → random ε → 用 forward marginal 做出 x_t。

Return：x_t、integer timestep、normalized t_model、ground-truth noise。

train_diffusion_model(...)
Training

標準 training loop：batch → predicted_noise = model(x_t,t_model) → MSE against ε → backprop。

x_t, _, t_model, noise = make_diffusion_batch(...)
predicted_noise = model(x_t, t_model)
loss = ((predicted_noise - noise) ** 2).mean()
ddpm_jump_posterior(x_t, x0_hat, t, s, alpha_bars)
Sampling

因為 sampling 可能從 t 一口氣跳到較早的 s，不只走相鄰 timestep，所以這裡算的是 respaced jump posterior 的 mean 和 variance。

DDPM、η sampler、sigma_hat 都會用到它。

sample_ddim(...)
Sampling

每一步：predict ε → 算 x̂₀ → 用 deterministic DDIM update 得到 x_s。沒有 fresh step_noise。

Endpoint 等於 sample_eta(..., eta=0)。

sample_eta(..., eta, ...)
Sampling

把 DDIM 到 DDPM 放在同一條連續軸上。eta=0 deterministic；eta=1 對應 DDPM jump posterior stochasticity。

Implementation 每一步都抽 step_noise，即使 η=0 用不到，這樣不同 η setting 消耗同一條 random stream，降低 comparison 中的 random-number confound。

sample_sigma_hat(...)
Control

Mean 還是用 DDPM jump posterior，但 variance 改成較大的 1 − alpha_jump。它不是「另一個主 sampler」，而是 stochasticity / variance choice 的 control。

sample_ddpm(...)
Sampling

每一步 predict ε → x̂₀ → posterior mean/variance → 抽 x_s = mean + sqrt(variance)·z。最後 s=0 不再加 noise。

Endpoint Algebraically 對應 eta=1；不同 arithmetic path 會造成小的 floating-point difference。

make_anisotropic_diffusion_batch(...)
Variant

跟 standard batch builder 一樣，只是 clean data source 換成 anisotropic GMM。Forward noise formula 不變。

train_anisotropic_diffusion_model(...)
Variant

Training objective 仍是 epsilon MSE；只是 batch builder 換成 anisotropic target。對應 Task 002。

train_diffusion_model_on_dataset(train_data, ...)
Variant

不再每 step 從 true GMM 無限抽新 sample，而是反覆從固定 train_data resample。這就是 finite-data experiment 的關鍵改動，對應 Task 004。

8. 讀一段 diffusion code 時，先問這 6 題

① 現在是 training 還是 sampling？
不要先看公式，先看 phase。
② 這裡的 x 是 x₀ 還是 x_t？
大部分 confusion 都從這裡開始。
③ noise 是 ground truth ε 還是 predicted ε̂？
④ 現在用的是 T 還是 NFE？
schedule grid 和 sampling budget 是兩件事。
⑤ 這一步有沒有 fresh random noise？
這通常就是 DDIM / DDPM / η 的差別。
⑥ 哪個東西被 fixed、哪個東西被 changed？
這決定 experiment 能不能做 causal interpretation。
最短閱讀路線： 如果你只是要重新進入這個 codebase，讀 make_diffusion_schedule → make_diffusion_batch → train_diffusion_model → sample_ddim → ddpm_jump_posterior → sample_ddpm。理解這六個之後，再讀 η 和 oracle control。
